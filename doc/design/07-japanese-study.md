# 07 · 日语词汇与语法学习

## 定位

在 DIY 功能目录增加独立的日语学习工具，复用 DIY 功能页的独立路由、轻量品牌栏和页脚约定。词库由项目随站点一起提供，用户打开后即可搜索、浏览和记录学习状态，不需要导入牌组或上传文件。界面以词库浏览与详情为主，同时提供可选的主动回忆背词模式。

## 项目内置数据

- 原始数据位于 `forest-bloom-web/public/data/japanese/`；清洗脚本为仓库根目录 `clean_japanese.py`，清洗后运行时数据位于 `forest-bloom-web/public/data/japanese/cleaned/`。保留原始 JSON，不要覆盖原始牌组文件。
- 红宝、绿宝各按 N1–N5 存放在 `redbook/N1cards.json` … `redbook/N5cards.json` 和 `greenbook/N1cards.json` … `greenbook/N5cards.json`。一个对象对应一条 Anki 笔记，包含 Anki 元数据以及对应牌组的原始字段。每本书以 N1 首条笔记作为字段样式示例，实际转换应依据字段名映射，不应依赖数组顺序。
- 通用 Anki 元数据包括 `__guid__`（稳定来源标识）、`__deck__`、`__notetype__`、`__tags__`、`__created_at__`、`__modified_at__` 及复习调度字段 `__reps__`、`__lapses__`、`__ivl__`、`__ease__`。清洗后 `sourceId` 保留 `__guid__` 或蓝宝 `Note ID`，`id` 使用 `__created_at__` 以兼容已记录的学习进度；复习调度元数据不进入运行时数据。
- 红宝词汇字段主要为 `Expression`（单词，可能以 `漢字[かな]` 同时包含汉字和读音）、`声调`、`中文释义`、`例句`、`惯用/関係`、`同音`、`Pronunciation`。释义、例句和关联内容可能带 HTML；音频值可能是 Anki `[sound:文件名]` 标记。
- 绿宝词汇字段主要为 `排序编号`、`日文`（常含 `漢字[かな]`）、`词性`、`释义`、`课号`、`音频`、`音调`。词性原文存在日文写法、缩写和多词性组合，不能直接当作统一分类值。
- Anki JSON 中的 `[sound:文件名]` 只是媒体引用，不包含音频内容；项目当前没有对应的 MP3 媒体文件，因此不能直接用这些文件名构造可播放地址。页面现阶段使用浏览器 `SpeechSynthesis` 日语语音合成朗读词条，实际音色取决于浏览器和设备已安装的语音。
- 蓝宝语法数据位于 `bluebook/grammar/N1cards.json` … `N5cards.json`。每条记录代表一个语法点，字段包括 `Level`、`Word`、`ConnectiveType1…10`、`Explain1…15`、`Example1…25`、`Chinese1…25`、`Note1…15`、`SentenceTag1…25`，以及音频、图片、顺序等字段；一个语法点可包含多个例句，编号字段是有序多值字段，空字符串代表没有该项，例句与译文按编号配对。
- `bluebook/exmple/N1cards.json` … `N5cards.json`（目录名当前拼作 `exmple`）属于独立的例句卡数据，每条记录表示单个例句，不是语法主记录的副本。本阶段只清洗 `grammar` 目录中的语法点及其内含的多条例句，不读取、不合并、不索引 `exmple` 目录。
- 清洗后每条记录统一使用 `id`、`book`、`level`、`kind`、`term`、`reading`、`writtenForms`、`partOfSpeech`、`meaningZh`、`examples` 和 `search` 等字段；词汇保留 `pitchAccent`、`relatedTerms`、`homophones`，语法保留 `connections`、`explanations`、`notes`，例句按对象数组存放。`search.meaningZh`、`search.kana`、`search.written` 是预生成的查询字段。
- 清洗脚本示例：在仓库根目录执行 `python clean_japanese.py`，从现有原始 JSON 重新生成 `public/data/japanese/cleaned/` 下的全部等级数据。蓝宝只读取 `grammar` 文件夹；`exmple` 中的单例句暂不纳入。
- 仓库根目录的 `export_anki.py` 是 APKG 转换工具，但输出仍是早期 `{id, front, back, category, partOfSpeech}` 格式，不兼容当前搜索页的规范化 schema；不要把它的输出直接放入 `cleaned/`。当前更新后的原始 Anki 导出 JSON 使用 `clean_japanese.py` 生成学习页数据。重新导入 APKG 后，需先整理为各书对应的原始字段结构，再运行清洗脚本，或另行扩展清洗器。
- 原始 APKG 在整理完成后按项目所有者要求删除；后续如需重新转换或核对牌组，需要重新提供源文件。
- 牌组来源和 CC BY-NC 4.0 许可记录在 `forest-bloom-web/public/data/japanese/ATTRIBUTION.md`，作为项目资料保留；学习页不显示来源链接。绿宝 N5 与蓝宝的上游作者/来源链接没有嵌入 APKG，待补充。
- 页面通过站点基础路径读取 `cleaned/{book}/N{level}.json`；已掌握和「还不熟」状态按稳定词条 ID 保存在当前浏览器，覆盖所有教材和等级；浏览教材/等级与背词教材/等级选择分别保存在本功能独立的 localStorage 键，刷新后恢复，不会覆盖其他数据。

## 搜索数据清洗方案

搜索需求包括按中文释义、假名读音、日文汉字/单词查找，以及对日文词条、读音和书写形式使用通配符。通配符中 `*` 匹配任意长度字符，`?` 匹配单个字符，按完整字段匹配；例如 `a*b*` 匹配以 `a` 开头、后续包含 `b` 的形式，`*あ*` 匹配任意位置含「あ」的形式，`あ*` 和 `*あ` 分别匹配以「あ」开头和结尾。纯大写重复格式符号可表达字符重复关系，例如 `AABB` 匹配前两个字符相同且后两个字符相同的四字符形式，`ABAB` 匹配第一/三及第二/四字符分别相同的形式；大写字母是位置变量而非需搜索的字面字母。通配符仅针对日文形式，不搜索中文释义。语法记录覆盖句型、接续、解释、语法主记录中的多条例句及其译文。保留原始导出，使用可重复运行的清洗脚本生成独立规范化数据。当前 `exmple` 中的单例句不在处理范围内。

### 规范化记录

以“一个词条/一个语法点一条记录”为单位，生成统一字段。当前实际清洗输出示例：

```json
{
  "id": "redbook-n1-1468570033420",
  "sourceId": "HJ:pZe~b4/",
  "book": "redbook",
  "level": "N1",
  "kind": "vocabulary",
  "term": "相容れない",
  "reading": "あいいれない",
  "writtenForms": ["相容れない"],
  "partOfSpeech": ["词组"],
  "sourcePartOfSpeech": ["連語"],
  "meaningZh": "不相容，互不两立",
  "pitchAccent": "①",
  "examples": [{ "text": "△相容れない関係/互不两立的关系" }],
  "relatedTerms": [],
  "homophones": [],
  "search": {
    "meaningZh": ["不相容，互不两立"],
    "kana": ["あいいれない"],
    "written": ["相容れない"]
  }
}
```

语法记录沿用 `id`、`book`、`level`、`kind`、`term` 和搜索字段，增加 `connections`、`explanations`、`examples`、`notes`。一个语法点仍是一条记录，`examples` 中按原编号将 `ExampleN`、`ChineseN`、`SentenceTagN` 配对。`exmple` 目录中的单条例句目前不纳入规范化结果。

### 清洗步骤

1. **保留原始输入**：当前 N1–N5 JSON 作为只读来源；规范化输出写到独立目录。每条记录保留来源牌组、等级和稳定 ID，便于追溯和重新生成。
2. **按教材显式映射字段**：红宝 `Expression` / `中文释义`、绿宝 `日文` / `释义`、蓝宝 `Word` / `ConnectiveType*` 等分别映射到规范字段。不要通过“第一个非空字段”猜词条或等级。等级优先取对应文件与 `Level`/牌组字段，出现冲突时报告错误，不静默猜测。
3. **稳定标识与去重**：红宝、绿宝以 `__guid__` 作为来源标识，并用原有 Anki 笔记创建 ID `__created_at__` 组成兼容旧进度的 `id`；不以数组序号或 `排序编号` 作为主键。蓝宝只读取 grammar 文件，以 `Note ID` 作为 `sourceId`、以 `__created_at__` 组成 `id`，检查其在各等级文件中唯一；`ExampleN`、`ChineseN`、`SentenceTagN` 作为同一语法点下的多条例句按编号配对。`exmple` 文件本阶段跳过，不与 grammar 合并。等级部分使用小写 N 值以兼容既有学习进度 ID。
4. **清理展示文本但保留原文**：解析 HTML 实体和标签，把段落、换行转换为文本边界；去除 `[sound:...]`，不把媒体文件名当作词义。清洗前原始字段仍可从原始 JSON 追查。不能简单删除所有括号，因为括号还承载读音、词性、语法注释或汉字注音。
5. **拆分读音与书写形式**：对 `漢字[かな]` 这类明确格式拆出 `headword` 和 `reading`，同时保留原始 `Expression`/`日文`。识别方括号、全角括号和 Anki 振假名样式时采用明确规则并记录无法解析项；不得将一般词义括号误判为读音。蓝宝语法例句里的 `漢字[かな]` 在例句层拆读音，不得覆盖语法点 `Word`。
6. **提取词性和中文释义**：词性先使用绿宝独立 `词性` 字段，其次从红宝 `中文释义` 开头等受限位置提取标签，再映射到统一类别；原词性标签保存在 `sourcePartOfSpeech`，无法识别的归入「其他」以供后续人工核对。中文释义保留完整清洗文本；不可因为定义或例句中出现方括号就把它当作词性。
7. **生成搜索变体**：中文索引使用释义、语法解释、例句译文和关联词；日文书写索引使用词条汉字形式与语法句型；读音索引从独立读音和带注音内容生成。查询时统一 Unicode 规范化、去首尾空白、折叠空白和常见标点；假名搜索可将片假名转平假名以兼容输入，但展示和原始值保持不变。
8. **通配符搜索匹配日文完整字段**：`*` 表示任意长度字符，`?` 表示单字符；片假名规范化为平假名后，对词条、读音和书写形式匹配。搜索不依赖正则表达式，也不匹配中文释义。
9. **校验与人工抽查**：生成时检查输入对象数组、词条非空和 ID 唯一；清洗脚本打印各书各级记录数，发现重复 ID 时停止。后续可扩充报告，统计读音缺失、未识别词性、蓝宝例句/译文配对异常和剩余媒体标记；`exmple` 目录不在本阶段校验范围内。应抽样核对清洗结果，未知词性保留于 `sourcePartOfSpeech` 并归到「其他」。

### 搜索索引与实施顺序

- 当前页面提供书本、JLPT 等级、词汇/语法、词性与学习状态筛选；搜索范围可选全部、中文意思、假名、汉字/单词或通配符。假名搜索将片假名归一为平假名；通配符模式使用 `*` 表示任意长度、`?` 表示单字符，并按完整字段匹配日文词条、读音及书写形式，例如 `a*b*` 表示以 `a` 开头且后续包含 `b`，`*あ*` 表示任意位置包含「あ」；纯大写模式如 `AABB`、`ABAB` 使用字母作位置变量，匹配字符重复结构。重复格式在搜索范围为「全部」时也会自动按通配符处理，不匹配中文释义。
- 规范化记录用 `search.meaningZh`、`search.kana` 和 `search.written` 支持分类搜索；语法接续、例句和中文译文纳入相应索引。蓝宝只用 grammar 主记录中的多条例句，暂不索引 `exmple`。
- 25,000 级别的纯文本牌组可先使用构建期生成的本地 JSON 索引和浏览器内检索；不需要把搜索专用拼音/假名变体重复放入每条展示数据。索引应去重、按需生成并可重建。
- 第二阶段再根据准确率需要增加词形还原、日文形态素切分、同义词扩展或更完整的词素前后缀。先用真实查询样例评估召回和误匹配，再决定是否引入词典或依赖；原始文本始终保留。

## 学习体验

- 独立 Hash 路由 `#/diy/japanese-study`，GitHub Pages 刷新可直接访问；页面可选择红宝书、绿宝书、蓝宝书及 N1–N5。
- 页面上方以教材卡片选择书本，红宝书和蓝宝书展示项目内封面，绿宝书使用主题化占位封面。初始显示完整选书区；选定后收起为当前教材缩略条，用户可随时展开更换，手机端卡片按窄屏尺寸排列。
- 使用独立的词库搜索与详情浏览布局，不要求沿用拼豆页面操作方式，也不强制翻卡；支持按词汇/语法、词性和学习状态分类，支持中文意思、假名、汉字/单词和通配符搜索。通配符 `*` 匹配任意长度、`?` 匹配单个字符；纯大写模式如 `AABB`、`ABAB` 将字母解释为重复关系变量，匹配完整日文词条、读音和书写形式。词库结果可切换「顺序」「五十音」和「随机」排列；顺序保留词库原始顺序，五十音按词条读音排列（无读音时按词条文本），随机模式对当前筛选结果洗牌，筛选条件变化时重新随机。
- 结果列表提供已掌握状态切换；详情展示释义、词性、接续、用法说明、例句和补充笔记，并可临时遮住中文释义进行自测。支持逐步加载长结果列表和导出当前等级学习进度 CSV。
- 「背词练习」与「词库浏览」使用独立界面状态。开始练习时快照当前书本、等级、筛选结果及练习队列；切到词库浏览、查看条目或更改浏览筛选/教材，不重置当前题目、队列位置或揭晓状态。练习页复用词库浏览的教材、JLPT 等级、搜索范围/输入和词性筛选控件：教材沿用封面卡片选择样式，选定后收起为封面缩略条并可再次展开；等级仍使用下拉选择。背词搜索针对当前练习教材与等级的词库，支持按中文意思、假名、汉字/单词或通配符筛选；通配符支持 `*`、`?` 及 `AABB` / `ABAB` 等重复结构，匹配日文词条、读音和书写形式；重复格式在默认「全部」搜索范围中也会自动识别。也可按该词库实际包含的词性（如动词、副词）过滤；输入或更改搜索条件不会打断当前题目，点击「按搜索结果练习」后才按匹配条目开启新队列。更改教材或等级后，当前搜索和词性条件应用于新词库；若该词库不含当前词性则自动恢复「全部」；浏览区的教材和筛选保持不变；返回练习时继续原位置。
- 背词义与背假名合并为同一练习队列和进度，不再拆分练习类型或进度。练习只将当前筛选结果中尚未标记为「已掌握」的词条加入队列；「还不熟」与未背诵词条都会继续参与练习，已掌握词条不会在本轮、重新进入练习或重新开始时出现；取消掌握状态或清除对应进度后才会重新加入。练习标题下以分段进度条展示当前筛选词条的「已掌握」「还不熟」「未背诵」数量；掌握与还不熟状态按稳定 ID 保存，未背诵由无状态记录识别。可勾选「随机顺序」打乱本轮未掌握词条；关闭随机顺序后，剩余词条按词库顺序排列。每题默认只显示不带注音的日文词条，不显示假名和中文释义，揭晓后同时显示假名与释义以及接续、例句。勾选「显示假名」后，题目同时显示假名和日文词条，揭晓时只需回想中文释义；勾选「显示汉义」后，题目预先显示释义，揭晓时回想假名；两项均勾选时词条和答案都可见，适合阅读复习。切换显示选项只隐藏当前揭晓内容，不改变题目位置或练习进度；提供「上一条」返回查看本轮上一词条，首条时禁用；「还不熟」保存待复习状态，「记住了」写入掌握进度并从本轮后续题目中排除。切换书本或等级会创建对应的新练习队列，但不会改变浏览区筛选状态。
- 词库列表、词条详情、背词答案和例句均提供扬声器按钮，通过浏览器 `SpeechSynthesisUtterance` 设置 `ja-JP` 朗读；不内置语音模型或音频文件，使用浏览器/设备提供的语音服务。页面提供朗读音色选择器，列出浏览器提供的日语 voice，默认由浏览器按 `ja-JP` 选择；用户手动指定后用于词条和例句朗读。音色列表在页面加载和浏览器 `voiceschanged` 事件时更新。点击后立即同步调用浏览器朗读，避免等待异步语音列表时丢失 Chrome 的用户操作授权。词汇优先朗读独立 `reading`，没有独立读音时朗读去除内嵌振假名标记后的词条。例句使用独立日文字段；红宝书例句若为「日文/中文」合并文本，则只取第一个斜线前的日文并去掉例句标记和振假名括号。开始朗读前取消旧语音；按钮在语音启动期间显示「正在启动」，收到浏览器 `start` 事件后才显示「播放中」，10 秒内未能启动、浏览器报告播放错误或缺少语音 API 时提示「该设备不支持播放语音」。再次点击同一按钮可停止，点击其他扬声器会切换朗读内容。语音结束、停止或离开页面时清除对应按钮的播放指示。此功能是语音合成，不是 Anki 原始录音；如要播放原录音，需另外导出并随站点提供对应媒体文件，再将媒体路径纳入规范化记录。
- 日文词条和例句使用 ruby 注音：原文含 `漢字[かな]` 时只在汉字上方标注假名；词条字段分开保存汉字和读音时，仅为汉字部分提供 ruby 注音，词条中原有假名按原文显示、不重复加注音。例句中的日语文字也应用相同规则。
- 规范化数据从项目 JSON 读取；已掌握与还不熟状态按稳定记录 ID 保存在当前浏览器 `localStorage` 的 `forest-bloom-japanese-study-progress-v1` 键，覆盖所有书籍与等级；教材选择保存在 `forest-bloom-japanese-study-selection-v1` 键，分别记住浏览与背词练习中选择的书籍和等级。提供三种独立清理：全局「清除全部进度」放在词库浏览/背词练习切换栏；「清除本书进度」放在教材选择区，按当前浏览教材移除该书 N1–N5 的已掌握和还不熟记录；「清除本级进度」保留在当前等级进度区，只移除当前浏览教材和等级中的已掌握及还不熟状态。全局清理经确认后仅删除日语学习进度键并清空当前练习队列与内存快照，保留书籍/等级偏好；局部清理保留其他教材/等级的状态，并同步调整相同教材练习队列。不调用 `localStorage.clear()`，不影响拼豆或其他功能数据。加载失败、进度损坏、清理或存储失败时明确提示。
- 保持 Forest Bloom 的雾蓝、暖白和柔粉视觉风格。移动端在 820px 以下点击词条后，完整详情直接在对应列表卡片下展开，并滚动到展开内容；再次点击同一词条或点击「收起详情」即可收起，点击其他词条则切换展开对应详情。不需要跳到列表底部或弹出遮挡列表的浮层。桌面端仍为词条列表与详情并排。520px 以下收窄页边距、压缩筛选控件并允许导航/操作按钮换行，词条列表改为适合窄屏的网格排布；360px 以下筛选项改为单列。播放指示遵循减少动态效果偏好设置。

### 汉字假名注音实现

- 注音由 `forest-bloom-web/src/components/JapaneseRubyText.vue` 集中处理，组件接收必需的 `text` 和可选的 `reading`。词库结果、详情、背词练习与日语例句复用该组件，避免各展示位置采用不同的注音规则。
- 组件将输入拆成若干文本片段。普通文本输出为 `<span>`；含读音的汉字段输出为 `<ruby>汉字<rt>假名</rt></ruby>`。样式将注音放在文字上方，并使用较小字号和浅蓝色。
- 优先解析词条文本内明确写出的振假名，支持汉字段后跟方括号或圆括号读音，例如 `漢字[かんじ]`、`漢字（かんじ）`，也兼容对应的全角方括号和半角圆括号。只有汉字段纳入 `<ruby>`，括号和读音作为标注内容，不会作为普通文字重复显示；原文中的假名部分仍按原样输出。
- 如果文本没有可解析的内嵌振假名，且提供了独立 `reading`，组件再尝试对齐词条与读音：按汉字段、假名段拆分词条；将片假名转换为平假名用于读音比对，但不改动页面上的原始显示；用词条中可见的假名片段在读音中定位边界，把相邻读音分配给前面的汉字段。词条末尾的送假名从读音末尾反向定位，避免它与读音开头的相同假名（如「勢い」中的「い」）误匹配。因此，送假名仍以普通文本显示，不会被重复标注。
- 对于找不到对应假名边界的片段，组件不强行猜测其余边界；无法安全解析或没有读音时退回原文显示。该逻辑是基于文字锚点的轻量对齐，不是日语形态素分析；无送假名的多汉字段、特殊读音或不规则读法可能无法精确拆分，遇到此类数据应优先在数据中提供明确的 `漢字[かな]` 注音，或改进清洗数据的读音标记，而不是把不确定结果附到假名上。
